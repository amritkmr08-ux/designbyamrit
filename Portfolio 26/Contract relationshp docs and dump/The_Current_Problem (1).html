01 · What the system shows

A folder tree.
Not an answer.

A user opens Sirion and navigates to the contract. What they find is a tree of folders and files. The structure tells them where things are stored. It tells them nothing about what anything means.

The folder tree is not wrong. It stores what was put in it correctly. But it was designed to answer the question "where is this file?" The question users actually ask is "what governs this contract?" These are different questions. Right now, the system answers only the first one.

02 · What users do instead

They build the
relationship model themselves.

When a system doesn't give users what they need, they don't stop needing it. They build it with whatever they have. These four patterns show up repeatedly across enterprise legal teams using Sirion today.

Observed · 01
The file name becomes the data model
"MSA_v3_FINAL_governs_SOW-Boston_supersedes_Amend2_EXECUTED.pdf"
→ The user needed to track the governing relationship, which SOW it applies to, and which amendment it supersedes. The system had no field for this. So it went into the file name.
Observed · 02
The relationship map lives in Notion
Confluence pages titled "Contract Family Structure." Excel sheets showing parent-child relationships. Visio diagrams of which MSA governs which SOWs.
→ The model users need exists. They built it. It just isn't in Sirion — it sits alongside it, maintained separately, going stale.
Observed · 03
Structure lives in one person's memory
When a legal ops manager left Morgan Stanley, her knowledge of "which amendment applies to which SOW" left with her. The new person needed weeks of handover.
→ The knowledge exists. It's just stored in a person, not the system. When they leave, it leaves too.
Observed · 04
Amendment hunting consumes review time
Legal ops teams report 15–45 minutes per contract review spent locating applicable amendments, cross-referencing dates, confirming what is currently in force.
→ A question the system should answer in seconds takes an expert half an hour. Every time.

Sources: Sirion PER-3956, PER-4715, PER-4787 · SC Feedback rows 19, 52 · Shared by Madhur Lakhanpal, Morgan Stanley session

What this reveals

Folders model location.
Contracts have meaning.
Location and meaning are not the same thing.

A folder can tell you
Where Amendment 4 is stored.
It cannot tell you
That Amendment 4 governs the Boston SOW, supersedes Amendment 2, and modifies Section 4.2 of the MSA.
03 · When the structure changes

Same question.
Instant answer.

The redesign doesn't change what data is in Sirion. It changes what the system understands about that data. Contracts become entities with explicit relationships — governs, modifies, applies to, supersedes. Documents become evidence attached to those relationships, not the relationships themselves.

The question "which amendment applies to this SOW?" goes from a 30-minute search to a single glance. Not because the data changed — because the structure changed. Relationships are now explicit, typed, and surfaced. The system knows what it knows.

04 · Why this matters beyond navigation

Every AI experience
reads this structure.

The relationship model is not just a better navigation UI. It is the substrate that every AI capability in Sirion reads from. When AskSirion answers a contract question, it is traversing this structure — or trying to guess at it from document text. The quality of the answer depends entirely on the quality of the structure underneath.

Without relationship structure
"Which amendment applies to the Boston SOW?"
AI reads all documents. Searches for mentions of "Boston" and "amendment" across 540 files. Returns a probabilistic answer based on text proximity. Might be right. Might not be.
→ User can't verify it. Can't trust it. Stops using it.
→
same question
With relationship structure
"Which amendment applies to the Boston SOW?"
AI traverses: SOW Boston node → "Applied Amendments" edge → Amendment 4 node. Returns: "Amendment 4 (CO3432). Applied Feb 2024. Supersedes Amendment 2. Confirmed by Priya on 14 Jan."
→ Deterministic. Auditable. Cited. Trustworthy.

The same AI model. The same question. Completely different reliability. The relationship structure is not a UI feature that sits on top of AI — it is the ground the AI stands on. If the ground is folders, the AI is guessing. If the ground is relationships, the AI is reasoning.
